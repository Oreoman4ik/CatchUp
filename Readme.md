# Описание контракта ошибки

Модели `ErrorResponse`, `ChainElement` и `ErrorDetails`
предназначены для передачи ошибки внешнему клиенту.

Техническая диагностика:

- stack trace;
- SQL;
- имя Java-класса исключения;
- URL с query-параметрами;
- токены;
- внутренние DTO;

должна оставаться только в серверных логах и связываться
с публичным ответом по `errorId`.

## ErrorResponse

| JSON-поле | Тип | Обязательность | Назначение |
|---|---|---|---|
| `errorId` | string (UUID) | обязательно | Идентификатор ошибки для корреляции с логами. Не меняется при передаче между сервисами. |
| `timestamp` | string (ISO 8601) | обязательно | Момент возникновения ошибки. |
| `status` | integer | обязательно | Итоговый числовой HTTP-статус от 100 до 599. Например, `404`, а не `"NOT_FOUND"`. |
| `message` | string | обязательно | Безопасное сообщение для внешнего клиента. Не формируется из `exception.getMessage()`. |
| `errorType` | string | обязательно | Стабильный публичный машинный код вида `BOOK_NOT_FOUND`. Это не имя Java-класса. |
| `currentService` | string | обязательно | Сервис, сформировавший текущий ответ. |
| `chain` | array | обязательно, минимум 1 элемент | Публичная цепочка распространения ошибки от исходного сервиса к текущему. |
| `details` | object | необязательно | Только типизированные публичные сведения из `ErrorDetails`. Если сведений нет, поле отсутствует. |

## ChainElement

| JSON-поле | Тип | Обязательность | Назначение |
|---|---|---|---|
| `service` | string | обязательно | Сервис, добавивший элемент. |
| `component` | string | обязательно | Публичное имя компонента. |
| `operation` | string | обязательно | Публичное имя операции. |
| `exceptionType` | string | обязательно | Стабильный публичный код причины. Это не имя Java-исключения. |
| `message` | string | обязательно | Безопасное публичное сообщение. |
| `timestamp` | string (ISO 8601) | обязательно | Время добавления элемента. |
| `status` | integer | необязательно | Числовой HTTP-статус. Отсутствует, если на этом шаге статус ещё не определён. |

## ErrorDetails

`details` не является произвольной map.

Разрешены только следующие поля:

| JSON-поле | Тип | Назначение |
|---|---|---|
| `resource` | string | Публичный код ресурса, например `BOOK`. |
| `violations` | array | Список ошибок валидации без возврата отклонённых значений. |
| `retryAfterSeconds` | integer | Неотрицательное число секунд до рекомендуемого повтора. |

Каждый элемент `violations` содержит только:

- `field`;
- `reasonCode`;
- безопасное `message`.

Отклонённое значение поля не возвращается, поскольку оно может
содержать персональные или чувствительные данные.

Пустой объект `details` недопустим. Если дополнительных сведений
нет, поле `details` следует полностью опустить.

## Правила безопасного сообщения

Публичные сообщения создаются из контролируемого каталога
сообщений или явно сформированного безопасного текста.

В публичных сообщениях запрещены:

- stack trace;
- полные имена Java-классов;
- SQL;
- строки подключения `jdbc:` и `r2dbc:`;
- URL с query-параметрами;
- токены, пароли и секреты;
- заголовок Authorization;
- переносы строк и управляющие символы.

Техническое сообщение исключения записывается только в лог
вместе с `errorId`.
